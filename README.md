# Folder Description

## report/

Contains the final report required by the assignment.

---

## output/

Contains the final deliverables.

These files are manually created by the group and will be submitted.

Files:

- 01-business-req-analysis-G08.md
- 02-erd-design-G08.md
- 03-logical-design-G08.md
- 04-design-validation-G08.md
- 05-db-definition-G08.sql
- 06-sample-data-G08.sql
- 07-query-design-G08.sql

These files are the final versions approved by the group after manual review and validation. They are used as the reference outputs for evaluating and improving the agent.

---

## evaluation/

Contains fixed evaluation rubrics.

Each file defines the scoring criteria for one section.

Rules:

- Each section is evaluated out of 10 points.
- The same evaluation file must be used for all rounds.
- Evaluation files must never change between rounds.

Purpose:

- Compare outputs consistently.
- Track improvements objectively.

---

## agent/

Contains the main agent definition.

This file stores global behaviors shared across all sections.

Examples:

- Requirement traceability
- Anti-hallucination rules
- Naming conventions
- Verification behavior

---

## skills/

Contains section-specific skills.

Each skill file contains specialized knowledge for one section.

Examples:

skill_03_LogicalSchema.md

- Convert entities into relations
- Identify candidate keys
- Verify foreign keys
- Preserve constraints

---

## experiments/

Contains all experiments for agent improvement.

Each section contains:

### result_round1.md

The raw output generated by the agent during round 1.

### result_round2.md

The raw output generated by the agent during round 2.

### result_round3.md

The raw output generated by the agent during round 3.

These files only store generated outputs.

Do NOT put evaluation results here.

---

### improve.md

Stores:

- Evaluation results
- Identified issues
- Agent improvements
- Skill improvements
- Overall observations

This file summarizes the entire improvement process for the section.

This file will later be used to write the report.

---

## prompts/

Contains reusable prompts.

generation_prompt.md

- Prompt used to generate outputs.

evaluation_prompt.md

- Prompt used to evaluate outputs.

---

# Workflow

For each section:

Step 1

Create a high-quality human-made output.

Store it inside:

output/

↓

Step 2

Use:

- DatabaseDesignerAgent.md
- Corresponding skill file

to generate the first output.

Store it inside:

experiments/section_xx/result_round1.md

↓

Step 3

Evaluate the generated output using:

evaluation/evaluation_xx.md

↓

Step 4

Record observations inside:

experiments/section_xx/improve.md

↓

Step 5

Improve the Agent and/or Skill.

↓

Step 6

Generate Round 2.

Store it inside:

experiments/section_xx/result_round2.md

↓

Step 7

Evaluate again.

↓

Step 8

Update improve.md.

↓

Step 9

Improve the Agent and/or Skill again.

↓

Step 10

Generate Round 3.

Store it inside:

experiments/section_xx/result_round3.md

↓

Step 11

Evaluate again.

↓

Step 12

Update improve.md.

# Agent Update Rules

Update the Agent if issues are related to:

- Hallucination
- Requirement traceability
- Naming consistency
- Output formatting
- Reasoning process
- Verification behavior

Examples:

Issue:

Invented attributes.

Agent update:

Add anti-hallucination rule.

---

# Skill Update Rules

Update the Skill if issues are related to:

- Missing entities
- Missing relationships
- Missing cardinalities
- Missing participation constraints
- Missing keys
- Incorrect SQL
- Missing edge cases

Examples:

Issue:

Missing candidate keys.

Skill update:

Add candidate key identification checklist.

---

# Overall Principle

output/

= Final deliverables

evaluation/

= Fixed scoring criteria

result_roundX

= Agent-generated outputs

improve.md

= Evaluation and improvement history

The experiment process is used to refine the agent.

The final submitted files remain the human-made outputs.
